# pq-verify 正式测试报告：AWS c7i.xlarge

## 结论

- **BoringSSL 的 SLH-DSA-SHA2-128s 验签比 liboqs 快 3.70 倍**（8,533 vs 2,306 次/秒，p50 115.8 µs vs 428.9 µs）。差距全部来自 SHA-NI：可移植构建里 BoringSSL 用纯 C SHA-256，两者几乎一样（2,324 vs 2,322 次/秒）。开发机 M1 上同一差距是 5.65 倍。
- **ML-DSA 优化构建比可移植构建快 3.9–4.3 倍**；**Falcon 的 AVX2 实现反而比纯 C 慢约 4%**；liboqs 的 SLH-DSA 两种构建都走 `slhdsa-c/portable`，结果相同。
- **错误消息、错误公钥的拒绝成本与完整验签相同**，所有算法都无法提前拒绝。签名长度错误时各实现都能快速拒绝，但 Falcon 仍需约 8.6–17 µs。
- **签名被改动的负例（`corrupt-*`、`extended`）存在测试工具引入的轮间波动**，在排除 SMT 和宿主机抢占之后仍然存在，这些行的数值只能作为量级参考，详见“已知问题”。

## 与计划的偏差

- **样本在服务器上重新生成。** 计划要求复制开发机的样本，但该环境禁止 `tsh scp`，改为在服务器上用同一 seed 重新生成。服务器上所有测试使用同一份样本，彼此可比；与开发机 M1 的结果输入不同，只能比较量级。
- **无法设置调频策略。** 虚拟机内没有 `cpufreq` 和 `intel_pstate` 接口，频率和 Turbo 由 AWS 虚拟化层控制，`cpupower` 无从生效。
- **有效签名的变异系数有 8 行在 0.02–0.03 之间**，超过计划的 0.02。原因是个别轮次慢约 8%，中位数不受影响，因此没有重跑有效签名组。
- **负例组补跑了一次**，见“已知问题”。
- **运行由 Agent 经 Teleport 在服务器上执行**，而不是计划写的由人执行，执行者经用户授权。

其余 SLH-DSA 参数集的规律与上表相同：签名内容被改动时都做完整验签，长度错误时在 0.4–1.6 µs 内拒绝。

- **错误消息和错误公钥**：所有算法的成本都等于完整验签，比有效签名慢 0–2.8%。
- **首部损坏**：只有 Falcon 在解析首字节时就拒绝（约 30 ns），ML-DSA 和 SLH-DSA 都要做完整验签。
- **尾部损坏**：Falcon 在解码签名时提前拒绝，成本约为有效签名的四分之一；ML-DSA 略快于有效签名。

- **安全含义**：没有可靠证据表明任何一种无效输入的处理成本高于有效签名。唯一的例外是 SHA2-128f 尾部损坏（1.67 倍），它属于下文的波动场景，两次运行都出现，原因未查明。

## 已知问题：签名改动类负例的轮间波动

首次运行的负例波动很大（例如 SHA2-128f 尾部损坏有 3 轮慢约 45%，BoringSSL 尾部损坏有 1 轮慢 5 倍）。为排除环境因素，补跑时下线了 CPU 3 的超线程兄弟 CPU 1，并用 `vmstat` 每 10 s 采样一次：

- 1,211 个样本中宿主机抢占时间（steal）全部为 0%。
- 两次运行的中位数基本一致：5 个亚微秒级的长度错误行快了 5–9%，SHA2-128s 尾部损坏快了 5%，其余变化都在 5% 以内。
- 波动依旧：负例 126 行中有 31 行变异系数 ≥ 0.02，慢轮只有正常速度的 0.6–0.8 倍；BoringSSL 首部和尾部损坏各有 1 轮只有 0.21 倍（变异系数 0.38）。

波动集中在测试工具会复制签名的场景：

| 场景 | 输入构造方式 | 慢轮 |
| --- | --- | --- |
| 有效签名、错误公钥 | 直接引用加载时分配的样本 | 无（有效签名只有约 8% 的个别慢轮） |
| 错误消息 | 复制消息，签名仍为引用 | 无 |
| 首部、中部、尾部损坏，追加字节 | 每轮重新复制签名再修改 | 大量，慢 20–80% |
| 截断 | 引用样本切片 | 少量（约 0.75 倍），只涉及亚微秒级的拒绝路径 |

推测原因是每轮复制的签名缓冲区落在不同的内存地址，某些对齐方式会触发缓存相关的减速（例如 4K 地址别名）。这一推测尚未用实验验证。它有两个影响：

1. 上表标 \* 的行，中位数取决于 5 轮中慢轮的个数，只能作为量级参考。
2. 有效签名的样本只在加载时分配一次，结果对应的是一次随机的内存布局。数据稳定，与开发机结论一致，但没有覆盖其他布局。

如需确认，可将同一份损坏签名放在不同对齐的地址上分别计时；若推测成立，应让测试工具固定或显式遍历缓冲区对齐。
